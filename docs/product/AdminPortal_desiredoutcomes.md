## Admin Portal — Desired Outcomes

### 1. Living Architectural Reference

Done looks like an Admin Portal that provides an accurate, visual, and expandable representation of the entire AVL Music Companion—including its application structure, services, integrations, data flows, database schema, dependencies, and the relationships between them.

A human or agent can begin at a high-level system view, expand any component for deeper context, and clearly understand how information moves through the product.

### 2. Listener Taste Knowledge Graph

Done looks like the portal being able to visually trace how a single signed-in listener’s identity, connected music-platform data, expressed preferences, behavioral signals, and configurable taste settings influence the events surfaced and prioritized for that person.

The resulting knowledge graph makes the recommendation logic understandable, traceable, and explainable rather than presenting the algorithm as a black box.

### 3. Shared Understanding for Humans and Agents

Done looks like Brett—particularly as a visual learner—and any AI agent or developer entering the project being able to quickly understand how the application is structured, how its parts are connected, where its source-of-truth information lives, and how the system is expected to be maintained.

The portal serves as a reliable shared reference that reduces guesswork, contradictory documentation, duplicated effort, and accidental architectural drift.

### 4. System Health and Connection Visibility

Done looks like the portal clearly showing whether the application’s databases, APIs, authentication providers, music-platform integrations, scheduled processes, and other critical services are connected and functioning as expected.

Gaps, stale data, broken connections, configuration conflicts, and other conditions requiring attention are visible without needing to inspect the codebase or multiple external dashboards.

### 5. Recommendation Quality and Listener Insight

Done looks like the portal providing an understandable view of why particular events are being prioritized, which listener signals influenced the ranking, and how recommendation outcomes differ between anonymous visitors and signed-in listeners.

The portal makes it possible to assess whether personalization is producing relevant, diverse, and locally valuable recommendations.

### 6. Content and Data Stewardship

Done looks like the portal providing a clear operational view of the events, venues, artists, partners, external sources, and community resources represented within the product.

Administrators can understand where information originated, whether it is complete and current, and how each record connects to the wider AVL Music Companion ecosystem.

### 7. Product Analytics and Usage Visibility

Done looks like the portal presenting Umami analytics in a clear operational view that shows how people are using the AVL Music Companion—including traffic, page engagement, referral sources, event interactions, sign-in behavior, and conversion actions—so product decisions can be grounded in real usage patterns.
